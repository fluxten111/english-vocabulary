## PR 自动检查（2026-11-04）

```sh

```

|要求|PR CI 检查|实际范围|
|---|---|---|
|构建检查|`npm run build`|静态构建验证：入口 HTML 中的本地脚本、样式和图片存在；递归检查浏览器字面量模块引用；全仓 JavaScript（含 Worker、测试和检查工具）语法检查。不会执行应用代码，也不生成打包产物。|
|已有单元测试|`npm test`|自动发现 Node 原生测试；保留原有 120 项单元及受控回归测试，增加 6 项构建检查与 2 项 Lint 环境行为测试。没有删改原断言。|
|代码规范|`npm run lint`|ESLint 基本 JavaScript 正确性规则，包含未定义变量、重复键、不可达代码、错误 typeof 等；区分浏览器、Worker 和 Node 环境，警告也导致失败。尚未建立 HTML/CSS 格式检查或全量风格规范。|
|类型检查|不适用|当前为 JavaScript，无 TypeScript/tsconfig，也未启用 checkJs；没有静态类型通过的结论。以后引入类型系统时须另加真实检查。|

`.github/workflows/ci.yml` 在 PR 创建、更新提交、重新打开和转为待审核时运行，不按文件路径过滤。仅有读取代码权限，不用服务密钥，不调用真实词典或付费批改，不部署 Pages/Workers。PR 连续更新会取消同一 PR 的旧检查。`package-lock.json` 锁定检查依赖；CI 使用 `npm ci` 安装，不在 CI 自动修复代码。

查看：进入 PR 的 **Checks** 页，再点具体任务查看日志；也可在仓库 **Actions → PR CI** 查看每次运行。三项任务均成功才表示这轮自动检查通过；本轮不配置主分支保护规则，是否允许合并仍由负责人决定。

**未覆盖的验收：**现有页面测试主要通过 VM 和事件替身执行，缺少真实浏览器端到端、视觉布局/跳动、实体手机键盘及真实外部服务的自动回归；30 个正式词的恢复验收仍有内容样本缺口。静态构建验证也不能证明外部资源可用或计算式动态 import 的运行结果。CI 绿色不表示以上项目通过，更不表示用户已验收 V0.1。下文旧测试数量均是各次历史记录。
