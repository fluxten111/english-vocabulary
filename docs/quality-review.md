# V0.1 PR质量审核流程

本轮只完善质量保障。Codex Code Review连接由用户暂缓；AGENTS.md提供将来审核的规则，不会自动启动服务。CI、AI审核、真实操作验证、用户验收分别记录。

## 规则来源和当前约束

来源：用户2026-11-04本轮六项审核要求；此前十条防回归红线；《项目执行与验收总标准》；产品《项目主要需求以及计划MD_V2.md》的V0.1适用条款及后续明确修正。私人原文保留在本机，不上传整套私人资料；后续PR提供相关摘录与批准依据。本页只保存已确认约束摘要，不代替完整产品规格。

|已确认约束|审核关注|
|---|---|
|网站仅V0.1；MD文档V2不等于网站V0.2|新版本、精简复习、新自动播放策略与音效等未经批准不得混入。|
|先复现、定位、最小修复；多模块先说明范围|先证明本次任务最终结果，再检查MD、用户要求、相关回归和通用系统规则。|
|声音/意义→先说后听→拼写/用法→可选造句→默写及必要弱项重练|阶段门槛、主动提示、原音与自己的录音、提交和揭晓顺序正确；不能以假回调证明真实可用。|
|准备整轮最多150秒，等待失败保留位置|挂起、刷新、重试和截止后结果不得无限等待或错误标为学完。|
|逐步保存、恢复、原词表与真实历史保留|保存失败、旧内容升级、备份导入和重练不覆盖首次记录；回退不清空数据。|
|现有完整手动再练属于V0.1|入口容易发现、无已学词时条件清楚、优先继续未完成再练；不能冒称已实现精简复习。|
|修复保留既有视觉结构|同尺寸/缩放/内容前后比较；检查播放、显隐、切词、长文本、图片慢加载、键盘、焦点、滚动与按钮位置。|
|中文提示框仅显示中文含义|来源/核对信息保留于数据及适当的来源说明，不混入提示正文；声音提示和教学中文两条路径都检查。|

## 每个PR怎样执行

1. **建立范围：**独立分支，以PR模板登记问题、复现、批准范围、MD/用户要求、预期画面与受影响模块。存在冲突先说明并等待依赖的决定；无关且获准的工作可继续。
2. **实施与本地验证：**先记录失败，再最小修复；对变更涉及的功能做针对性与旧功能回归。执行`npm ci --ignore-scripts --no-audit --no-fund`及`npm run ci`，保存提交、环境、命令、结果和未覆盖项。
3. **远程CI：**PR opened/synchronize/reopened/ready_for_review触发构建、测试、Lint三项。到Checks或Actions→PR CI查看日志，核对run.head_sha等于当前PR head；旧成功或取消/跳过均不能充当当前成功。类型检查当前不适用。
4. **审核：**人或后续启用的Codex依据AGENTS.md审核差异及受影响链路。按优先级、证据、影响和最小方案提交意见；既有问题与新引入问题分开。审核任务不直接改产品代码。
5. **修正与复核：**按批准范围处理意见；每次新提交重新核对CI与受影响验证。是否再次触发AI审核须在服务启用后实测，当前不预填。失败/阻塞保持可见。
6. **用户决定：**提交具体结果、画面证据、未解决项与回退点，由用户体验验收、决定合并及发布。保留Git检查点；main推送会触发既有Pages发布，因此合并有上线影响，不能自动执行。

本地`npm run ci`与GitHub独立runner是两份证据；远程CI依然执行项目现有测试，独立执行不意味着额外覆盖了用户路径。

## 完成判断

|阶段|允许作出的结论|
|---|---|
|文件已进入PR|审核规则已提交，待合并；不能声称main或后续PR已继承。|
|本地检查通过|只证明所列本机范围；不声称远程成功。|
|最新SHA三个远程job成功|当前自动检查通过；不声称产品无缺陷。|
|AI产生符合规则的实际报告|才记录AI审核跑通；配置文件存在不等于已启用。|
|用户明确体验通过/批准合并|按用户实际决定分别记录，不推导下一版授权。|

现阶段尚未配置强制分支保护、强制审核或自动验收门禁。模板复选框是人工核对，不能阻止点击合并。后续如配置硬性门禁，需明确用户决定、必需检查名称和恢复方式。

## 怎样验证整套流程

- **本轮正向验证：**把规则/模板更新到当前CI PR的新提交，观察synchronize是否产生新run；核对head SHA和三项结果。这里不引入产品缺陷。
- **后续失败门禁验证：**在获准的临时测试PR中，仅让独立检查样例确定失败，验证CI红灯与（若已配置）合并门禁；恢复后再核对绿灯。不得改main、削弱真实测试或把故障混入产品PR。当前尚未执行。
- **AI规则验证（服务启用后）：**用一个已知违规样例、一个安全修复、一个无关改动测试能否指出有效问题、避免误报。记录规则引用、行号、影响和建议；不要预先声称审核成功。
- **真实体验验证：**选择一项用户已确认的V0.1问题，在单独修复PR中完成“复现→修复→针对检查→旧功能回归→用户验收”。页面跳动需真实浏览器几何/滚动与视频，文案需直接检查最终内容；适用手机项目仍需实体设备。

规则写法参考[OpenAI官方Code Review规则说明](https://developers.openai.com/blog/custom-code-review-rules-for-codex)：仓库级规则放根AGENTS.md，并用违规、安全和无关样例验证；规则不能取代测试和强制审批。
